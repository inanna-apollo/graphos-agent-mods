# Spike results and engine notes

Observed behavior of the Claude Code mod API and GraphOS Agent Services. These notes record the evidence behind implementation choices; the README covers usage.

### Shapes the code relies on

- `tool.call` `e` keys: `operation`, `variables`, `tool`, `tool_use_id`. `variables` is `{} | string`.
- `$.mcp.call` returns `{ content: [{ type: "text", text: "<json>" }], isError }`. The JSON text holds the payload.
- `validate`: `{ bundleDigest, requestId, scope, valid, errors?: string[] }`. When invalid, `errors` holds compiler text that quotes the operation (untrusted), and one string can contain several `Error:` blocks.
- `bundleDigest` changes mid-session (seen `e5f6…` → `a1b2…` within hours), so the cache must key on it.
- `introspect`: `{ bundleDigest, requestId, scope, types: string[] }` (SDL strings).
- `dry_run`: `{ bundleDigest, results: [{ denyOperation, fields: [{ decision, path }] }] }`. `path` is a dotted response path built from **response keys, so aliases are used** (`hits: confluence_search { items: results { heading: title } }` → `hits.items.heading`). The IR builds each field's path from `alias ?? name` and maps it to the schema coordinate. The real name is always what gets shown.
- Agent Services errors carry `extensions.code`. `UPSTREAM_AUTH_REQUIRED` includes `sources[].authorizationUrl`, which the pane should show as its own state.

## Permission checks on a plugin's own calls

- A hook's `$.mcp.call` is permission-checked like a model tool call unless a person's command or press is behind it, and its dialog queues behind any pending one.
- Enrichment runs from a `$.clock.every` pump started in `session.start`, which supports work spanning multiple events.

## Engine facts learned building the pane (Oct 6 2026, 2.1.290–2.1.292)

Each was verified with a probe or live in the tester; the code depends on them.

- **Hover cards.** An absolute Box over the pointer counts as on its parent, so a layer spanning rows blocks the hover triggers beneath it. The engine clips an absolute Box to a zero-height absolute parent. Each card is therefore a direct child of the pane root, placed with `top` below its trigger or `bottom` above it. `bottom={0}` on a root child lands on the last content row, because the root's height is its content's. Later siblings paint over earlier absolute Boxes, so cards are placed last.
- **Sticky hovers.** A revealed hover Box joins its group, so it remains visible while the pointer rests on it. A card that spans the next row's trigger keeps the previous card visible, so row tips are placed inside their own row.
- **Fragments** drop nested arrays. Use a Box.
- **Buttons** take no color, and a plain Button draws its hotkey in the accent color.
- **Markdown links** draw in ANSI 94, which is gray in some themes. Inline code inside a link draws in 256-color 153, a fixed light blue. With `onLinkPress` and `pressableLinks`, a plain click presses the link.
- **`$.ui.notice`** is accepted but not drawn for MCP tool dialogs, so the verdict line decorates the call's `ToolUse` / `ToolGroup` row instead.
- **Reads.** A dispatch's `$` reads one moment. A pump started on a `tool.call`'s `$` never sees later writes while that dialog is up, so the pump runs on the session's `$`.
- **The harness pointer** reaches only `Client` elements, and tmux-sent mouse events don't hover, so hover is checked by hand.
- **`tool.check`.** A `tool.check` hook can lift the engine's `ask` to `allow`; this mod does so only for a call that fits the person's trust rules, never past a deny or an organization `ceiling`. A `tool.check` hook's `e.input` is `{ operation, variables }`, and `e.tool_use_id` is set on the model's own calls.

## Engine facts for the standing line, attribution, spinner, file watch and transcript RESULT (Oct 6 2026, 2.1.292)

From the reference docs (`.claude-plugin/types/claude-code/index.d.ts`) unless marked *live*. Seen live in the tester (Oct 7 2026): the standing line, the learned-site line, the transcript RESULT block, `/gas setup` and its prompt-box draft, the receipts line and `/gas links`. Not yet seen live: the spinner text, a subagent's label, and the notices on saving trust.graphql or links.toml. Each entry lists its remaining checks.

- **Standing line.** `$.ui.status(text)` pins one line per plugin under the prompt until another call replaces it (`undefined` clears it; 2000 characters drawn). `SessionMode` supplies the footer's dim mode labels (`focus`, `memory paused`), joined by ` & `. A dispatch reads a fixed state snapshot, so the status line uses the value returned by `update`. *Seen live (Oct 7):* under the terminal prompt. *Check:* Desktop rendering and removal of stale state after `/clear`.
- **Subagent attribution.** `tool.call` and `tool.check` carry `e.agentId` for subagent and teammate calls; it is absent for the main loop. `$.agent.list()` returns an agent's `type` and `description`, but may omit workflow-started agents and engine forks. Unknown IDs display `from subagent`. A label lookup takes at most 5 s and updates the call asynchronously. Known labels use `type: description`; teammates display `from subagent · teammate: …`. `tests/agent.test.ts` passes `agentId` through `$.tool.call({ …, agentId } as never)` in the harness. *Check live:* an Explore agent's call displays its type and task.
- **Spinner.** `Spinner` props are `word`, `message` (a state's override, else null), `suffix` (the ellipsis) and `mode`; none names a tool or a call, and the instance's `requestId` is the agent id. `mode: 'tool-use'` spans the whole tool phase (the engine sets it when the assistant message ends), so a permission dialog and the execution it leads to are one mode. The reference docs say nothing about the spinner while a dialog is up, so the hook claims it only for a call whose permission check answered allow (the engine's own rule, or our trust-rule lift), where no permission dialog can be: the check hook starts the text, the headline's arrival updates it, and the call's end (or an abort, an orphan's settle, session.end) clears it. The text is one small atom, so a spinner row subscribes to it and to no call's state; the hook is matched on `mode: 'tool-use'` so other modes cost nothing, and leaves a spinner whose `message` is already set alone. *Not yet seen live; check:* whether the spinner is drawn at all while a dialog is up; if it is not, calls that ask could be named too once they run (drop the allow condition in the check hook), and the headline's arrival redraws the row.
- **Config file watching.** `classic.SessionStart` can return absolute `watchPaths`, including paths outside the project. The engine raises `classic.FileChanged` with `{ file_path, event: 'change' | 'add' | 'unlink' }`; the path matches the one supplied and can be used in a hook matcher. A user settings hook may replace the watched paths until the next session. Saving `trust.graphql` produces a notice without reloading its rules (see `.claude/CLAUDE.md`). Saving `links.toml` reloads it after a 300 ms debounce, combining an editor's unlink/add sequence. The transcript reports loaded and skipped row rules and newly configured origins. *Check live:* each save produces one notification.
- **Transcript RESULT.** A standalone result emits `ToolResult` with `tool_use_id`, `tool`, `output`, and `isErrored`. `ToolUse.output` and group-call `output` contain the same record. Expanded groups draw results inside their `ToolUse` rows, whose props do not identify whether they belong to a group. Adding a result block there would duplicate standalone results, so expanded groups receive no extra block. Folded groups show a count line; the `ToolGroup` hook adds each result below its verdict. Blocks precede the unchanged `next(e)` rendering. Rows look up an in-memory record by `tool_use_id`, written at settlement and after analysis. A missing record is populated from calls state, subscribing the row until its next draw. Reloaded modules recover blocks for the last 20 calls from session state. Record links use `Markdown` with `onLinkPress`, and `surfaceOpened` outside the terminal. *Seen live (Oct 7):* the block. *Checks remaining:* placement above the engine's MCP result; `ui.press` from a transcript record link; grouping of Agent Services calls (one fold was seen in the initial spike); and narrow-width rendering.

## Learned sites, /gas setup, the store and the manifests (Oct 6 2026, 2.1.292)

- *Live (Oct 7):* Agent Services reaches Jira through Atlassian's API gateway, so every `self` in a Jira answer is `https://api.atlassian.com/ex/jira/<cloud id>/...`, which names no site. That includes `jira_getCurrentUser { self }`, the first setup question, which did not identify a tenant. A status's and a priority's `iconUrl` stay on the site (`https://<name>.atlassian.net/images/icons/statuses/...`), so `iconUrl` is a URL key. The Atlassian setup question asks five issues for `fields: ["status", "priority"]`: on a clean install (Oct 7) one issue's status did not identify a tenant, because a status Jira Software manages (In Review) has its icon on the gateway too, while every priority icon seen was on the site. `slack_authTest { url }` identified the Slack workspace.

From the reference docs, the test harness and `claude plugin validate` unless marked *live*. Seen live (Oct 7): the learned-site line (Slack, then Atlassian), `/gas setup` with its prompt-box draft, and `/gas links`. Each entry lists its remaining checks.

- **Learned sites.** A site is taken from an Agent Services response in `tool.call`, before `outcomeOf` runs (record URLs are worked out inside it), and from the saved copy of an oversized result. Tenant discovery parses a response only when the Atlassian site or Slack workspace is still unset (`baseSources` from `loadLinkConfig`). A learned site is kept in `$.store` under `learnedSites` and checked with `tenantOf` on every load. A drawn row works its links out from the current link config, so a site learned a moment later still reaches rows already drawn; discovering the site before building the outcome gives stored previews the correct URL. `/gas setup` drafts two read-only queries, one for each unset site: `slack_authTest { url }` and five issues from `jira_searchAndReconsileIssuesUsingJql` with `fields: ["status", "priority"]`. *Live (Oct 7):* both answered on a real Agent Services and each identified its site (Slack's from `url`, Atlassian's from a status's `iconUrl`), the learned-site line once for Slack and then once for Atlassian.
- **`$.store`.** A JSON file of the plugin's own, `get` of an unset key is `undefined`, `set` rejects past 4 MiB. Keyed by plugin name; a renamed plugin starts it empty (so the snapshots and timing flags start off). The harness takes `store.get`, `store.set` and `store.delete` hooks like any event, answering `{ value }`. *Check live:* that a learned site is still there in the next session.
- **`$.session.version()`** answers `{ version, base?, builtAt? }`; a development build's `base` ends in `-dev`, which `isOlder` cannot compare (it takes dotted releases only), so `/gas setup` reports that the version cannot be compared. A throw is read as an unknown version, and nothing is logged. *Check live:* the session-start line on a release older than 2.1.290, if one is at hand.
- **`$.prompt.fill` from a command.** `/gas setup` fills the prompt box from a command's dispatch, as the access-request button does from a press. The hook answers `{ isFilled, refusal }` itself while `prompt.read` wraps `{ value }`, in the test harness. *Live (Oct 7):* the composer takes the draft right after `/gas setup`. *Not recorded:* that it appends after what was already typed.
- **Options are not checked against the manifest in tests.** `{ options: { snapshots: true } }` is accepted for a key `plugin.json` no longer declares, so a test can hide a missing declaration. Snapshot options were removed from `userConfig`; `/gas snapshots on` enables snapshots. The defaults are off, with widths of 50, 64, and 84 columns.
- **`claude plugin validate`.** It validates `.claude-plugin/marketplace.json` too. A marketplace's description sits under `metadata.description` (a bare one warns), `"source": "./"` and an owner name pass, and `displayName`, `homepage`, `repository` (a string), `license` and `keywords` in `plugin.json` raise no warning. `--strict` passes with the repo's own guide at `.claude/CLAUDE.md`, where Claude Code loads it as project memory; at the plugin root it was the one warning, because a `CLAUDE.md` there is not loaded.
- **Installing from GitHub.** *Live (Oct 7):* `claude plugin marketplace add inanna-apollo/graphos-agent-mods` and `claude plugin install graphos-agent-mods@graphos-experiments` in a fresh profile clone the repository over SSH, or over HTTPS where SSH fails. `plugin.json` has no `version`, so the plugin is versioned by commit and an update reaches people who already installed; no lockfile is tracked, because a `package.json` with a lockfile at the root makes the install run npm.
- **Hover tests are close to the harness's 5 s limit.** The slowest (`GnarlyOverview`, `trusted`, `asked`) take 3 to 7 s and can time out on a busy machine; run the suite again before suspecting a change.

## What the context receipts assume (Oct 6 2026)

The receipts line was seen live in the tester (Oct 7 2026); each entry lists its remaining checks. The receipts (src/weight.ts, src/view/receipt.ts) read only what the mod already read: the result's text, and for an oversized result the file Claude Code saved.

- **Units.** Claude Code's own stand-in says `Output too large (58.2KB)` and `src/result.ts` has always read a KB as 1,024 bytes; the receipts say KB the same way. *Check:* a result whose stand-in says N KB reads as about N KB in the pane.
- **What Claude saw of an oversized result.** `<persisted-output>` carries `Preview (first 2KB)` and the saved path; the older `exceeds maximum allowed tokens` text carries the path and no preview. The receipts say "a short preview and its path" for both. *Check:* what Claude is actually shown for each form; the older one is the less exact claim.
- **Compact bytes.** The measured size is compact JSON encoded as UTF-8. It excludes whitespace introduced by a service's pretty-printing. Estimated tokens are bytes divided by four; the actual count depends on content and tokenizer. *Check:* whether Agent Services' `execute` text is compact (`curl`-style single line) or indented; if indented, the measure undercounts by the indentation.
- **The saved file.** A saved tool result is content blocks pretty-printed, the response text inside as a string; `responseOf` unwraps it once, so the weight is the inner response's. `$.fs.read` of it is bounded by `MAX_SAVED` (2,000,000 characters); a larger file is not read back, and the outcome stays `isTooLarge` with Claude Code's own figure.
- **Reading is counted once.** The standing line's bytes are added when a call's outcome is recorded (`countRead` in the `tool.call` hook), once per call; a call whose outcome was read back from a saved file is not added (Claude received only the preview and saved path). `$.state` keeps the total as `tally.bytes`, absent in state an older build wrote (counted as none).
- **Cost.** The walk is one pass over the parsed response after `JSON.parse`: in Node, a 1.2 MB response of 78,000 values took 17 ms (its `JSON.parse` 3 ms), so a response at the 2 MB read-back bound is a few tens of ms. It runs in the `tool.call` hook after `next(e)` returns, before the row draws. *Check:* a large live result does not visibly stall the call's row.

## What the write preview assumes (Oct 7 2026)

The write preview runs no Agent Services call of its own. The argument and return shapes are the Agent Services schema as read on Oct 7 2026, and the rest is from the vendors' API documentation. Each entry lists a check using read-only queries or inspection of an existing write dialog. Do not approve a write for testing.

- **Argument shapes.** Jira's `fields`, `update` and `transition` are opaque JSON; a model may pass them as objects in `variables` or as JSON strings, and both are read. Slack's `blocks` and `attachments` are strings, URL-encoded JSON in Agent Services' description; plain JSON is read too. *Check:* a real write's dialog shows the shapes the fixtures use.
- **What a response carries back.** Jira answers a transition, an edit (unless `returnIssue`), an assignment and a delete with no content, so RESULT confirms nothing for them; Confluence's page update returns the page (`title`, `status`, `version.number` when selected); Slack's post returns `ts` and `message.text`. *Check:* what `execute` returns for each, on a write someone else made on purpose, or in a sandbox, never by running one to test.
- **What a delete leaves.** Jira has no trash for issues or comments, Slack none for messages, and Confluence comments are deleted for good; a Confluence page or blog post deleted through the v2 API goes to its space's trash. This is from the vendors' API documentation, not observed. *Check:* the flag and the note against the vendor docs when the Agent Services bundle changes.
- **Broadcasts.** Only `<!channel>`, `<!here>` and `<!everyone>` (and a rich-text `broadcast` element) are flagged; a literal `@channel` typed as text is not, since Slack's post API does not link names unless asked. *Check:* whether Agent Services' `slack_sendMessage` sets `link_names`.

## A plugin's own `execute` call (Oct 7 2026, 2.1.292, *live*, read-only)

A throwaway probe plugin (never shipped) asked to run one fixed read, `query ProbeSelfRead { slack_authTest { url } }`, through `$.mcp.call(server, 'execute', …)` from a slash command, beside this mod in manual mode. It was declined at the dialog.

- **It raises its own dialog,** headed `Tool use · from the <plugin> plugin`, like any ungranted call. This matches spike 4.
- **The mod initially displayed the probe without plugin attribution.** The origin is now recorded: `next.origin.plugin` in `tool.call` is `engine` for Claude's own calls and the plugin's name otherwise. The pane displays `↳ from the <plugin> plugin` and a hover card.
- **No `classic.PermissionRequest` line appeared** from the probe's hook before that dialog. Either the event did not fire for a plugin-made MCP call, or the `$.ui.log` from it was not drawn. *Check:* the same hook on a model-made Agent Services call's dialog.
